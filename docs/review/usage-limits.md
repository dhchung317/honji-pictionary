# Usage limits

## Running this review

These changes are local, based on commit `6c3fb66` on `fix-vh`. Nothing has been pushed or deployed. Use a development Redis/Blob store for failure, concurrency and limit tests; avoid exercising these against the production game.

Open the review folder in your editor. Its `node_modules` currently links to the original repo's installed dependencies. For a fresh checkout use `npm ci`. Configure the same required environment variables locally, preferably using separate development credentials. Do not commit `.env.local`. Start with `npm run api` and open the local URL it reports. If Vercel asks to link a project, choose your development project. `npm run ui` alone does not provide the server endpoints.

First play one normal game with a host browser and two players in separate browser profiles/devices: join, draw avatars, start, draw, submit, view results, quit. Reload each browser once while waiting in the lobby. Confirm that normal gameplay still works.

Automated checks use mocked services; they do not call Redis, Blob or OpenAI. Live multiplayer and hosted service integration remain manual checks.

## What changed

Adds fixed-window Redis request limits, 10 player slots per room, 15-character names, 2 MiB uploads, one-minute upload tokens, exact upload paths and validation of drawing URLs/Blob metadata. Global room creation and round starts are capped at 100 per hour. Creating rooms is capped at 10 per hour per source address; starts at six per hour per room. Upload and submission actions have six-per-minute limits per player; uploads also have 60-per-minute room limits. Joining has a 24-per-minute room limit. Redis failures fail closed for limit checks.

## Test

1. Play a normal game, including avatar updates and auto-submission. Confirm random-suffix Blob URLs are accepted.
2. Join 10 players, then an 11th: expect 409 with a room-full error. Repeat using simultaneous joins; the Redis admission check is atomic.
3. Try a name longer than 15 characters: expect 400. The join page displays the API rejection message; its name input also limits entry to 15 characters. Duplicate-name suffixes fit within that limit.
4. In the development environment, create 11 rooms from one address within an hour: the 11th should return 429. Confirm Retry-After is included. Prefer temporarily lowering the limit in your local copy to test recovery after its window expires; restore it afterward.
5. Request a token for another upload path or upload an image over 2 MiB: expect rejection. PNGs generated by the current 500px canvas should upload normally.
6. Replace a drawing URL with an external URL, another player's URL, an avatar URL, or a missing Blob URL: expect 400. A correct uploaded drawing should succeed.
7. Disable development Redis briefly: limited actions should return 503 instead of silently bypassing the limits.

`node --test tests/usage-limits/regression.cjs` checks URL rejection, over-limit behavior and Redis failure behavior. Atomic player admission and actual Blob validation require the live checks above.

## What might break / limits

Schools/parties behind a shared address can hit the room-creation cap. Production source-address extraction relies on Vercel's forwarded-address header; other reverse proxies need configuration. Local runs share the loopback address. Frequent avatar updates and submission retries can hit limits. Larger imported images are rejected. Limits are MVP defaults and should be tuned using actual traffic. They limit usage, but do not replace provider spending caps or Blob retention/cleanup. Room slot records can remain until expiry if player creation fails after admission.
